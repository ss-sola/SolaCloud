# 知识库附件向量化实现逻辑

## 模块总览

RAG 知识库的附件向量化链路位于 `apps/rag-service/src/modules/knowledge/`。

当前链路支持两种附件输入方式：

1. 直接传入完整附件信息：`fileName`、`mimeType`、`filePath`
2. 只传 `fileId`：服务端会从 `middleware_file_item` 读取 `original_name`、`storage_path`、`mime_type`，再结合 `UploadRootDir` / `UploadPublicBaseUrl` 还原真实文件路径与引用地址

这样可以直接消费 middleware-service 已上传的文件记录，不再要求前端传本地文件路径。

## 实现逻辑

### 1. ingest 入口

- 接口：`POST /api/knowledge/ingest`
- 入参：`knowledgeBaseId` + `attachments[]`
- `attachments` 中每项优先使用 `fileId` 解析；若无 `fileId`，则要求显式提供 `fileName`、`mimeType`、`filePath`

### 2. 附件解析

`KnowledgeService` 会先把附件解析为统一结构：

- `fileId`
- `fileName`
- `mimeType`
- `filePath`
- `fileUrl`

如果传入 `fileId`，会查询 `middleware_file_item`，再拼出：

- `filePath = path.resolve(UploadRootDir, storage_path)`
- `fileUrl = UploadPublicBaseUrl + '/' + storage_path`

### 3. 异步处理流程

创建 `rag_knowledge_document` 记录后，异步执行：

1. 文档解析
2. 文本分片
3. 批量 embedding
4. 保存 `rag_document_chunk`
5. 回写 `processing_status`、`chunk_count`

### 4. 文档格式支持

`DocumentProcessorService` 当前支持：

- PDF
- Word（doc/docx）
- PowerPoint（pptx）
- Excel（xls/xlsx）
- txt / markdown

其中：

- `pptx` 通过解压 OOXML 后提取 slide XML 文本
- `xlsx` 通过工作表逐行展开为纯文本

## 接口变化

### `POST /api/knowledge/ingest`

单个附件项从“必须传 `filePath`”扩展为：

- 传 `fileId` 即可
- 只有在没有 `fileId` 时，才要求 `fileName`、`mimeType`、`filePath`

这使得附件上传成功后，可以直接基于 `middleware_file_item.id` 发起知识库向量化。

## 服务间文件调用

`FileServiceClient.getFileDetailBatch()` 通过只读的 `POST /file/batch-detail` 批量取文件详情，可在公共客户端允许的瞬时故障下重试。`PUT /file/description` 使用幂等写策略，单次回写的各次尝试携带同一 `Idempotency-Key`。写重试开关默认为关闭，部署接收端与幂等记录表后再开启。

附件描述回写可从父操作和文件 ID 派生步骤键，使同一个队列任务重投时仍能识别首次写入。相同键再次提交不同的描述会收到 HTTP 409，保留首次写入。写回失败向任务调用方抛出错误，结束本次任务的后续向量化。下载或模型生成失败仍按原有规则返回降级描述。模型生成与向量化调用维持单次发送策略。

## 配置项

RAG 服务新增复用以下配置：

- `UploadRootDir`：共享上传根目录
- `UploadPublicBaseUrl`：共享上传访问前缀

这两个配置应与 middleware-service 保持一致，否则 `fileId` 模式下无法正确定位文件或回填引用地址。
