# 聊天模块

## 职责

提供基于 RAG（检索增强生成）的智能对话能力，支持多轮会话、流式输出、来源引用。

## 接口清单

| 方法   | 路径                      | 说明                 |
| ------ | ------------------------- | -------------------- |
| POST   | `/chat/session`           | 创建聊天会话         |
| GET    | `/chat/session/list`      | 获取会话列表         |
| GET    | `/chat/session/messages`  | 获取会话历史消息     |
| DELETE | `/chat/session`           | 删除会话             |
| POST   | `/chat/send`              | SSE 流式聊天         |
| POST   | `/chat/similar-queries`   | 获取相似历史问答推荐 |
| POST   | `/chat/session/summarize` | 手动生成会话摘要标题 |

读取历史、发送消息、生成摘要和删除会话通过当前登录账号查找未删除的自有会话。未登录返回 `403`，会话不属于当前账号或已删除时返回 `404`。发送接口在开启 SSE 前完成校验，Deep Agent 在创建工作区和调用模型前同样校验会话归属。

## 实现要点

### 文件附件处理

- 前端预上传文件至 middleware-service，将 `fileId` 列表随消息发送
- 后端通过 `FileServiceClient.getFileDetailBatch` 批量获取文件详情
- 文件下载到临时目录后按 MIME 类型分发处理：
  - 文本型（PDF/Word/PPT/Excel/TXT/MD/CSV）：复用 `DocumentProcessorService` 解析为纯文本
  - 图片：读取二进制 → base64 → 发送给 GPT-4o 多模态模型生成描述
  - 音视频：复用 `MediaProcessorService`，返回占位文本
- 文件内容与用户 query 组合为结构化 prompt：`[附件内容]\n📎 filename: <解析文本>\n\n[用户问题]\n<query>`
- 临时文件在 `finally` 块中清理
- 附件元数据持久化到 `ChatMessage.attachments` JSONB 字段

### SSE 流式响应

- 使用 NestJS `@Sse()` 装饰器 + `Observable<MessageEvent>`
- 事件类型：`token`（逐字输出）、`done`（完成）、`error`（错误）、`sources`（来源引用）
- 禁止缓冲：设置 `Cache-Control: no-cache`、`Connection: keep-alive`

### 来源引用

聊天来源引用包含：`chunkId`、`documentId`、`fileId`、`fileName`、`fileUrl`、`score`
前端据此渲染 FilePreview 组件。

### Deep Agent 运行时

RAG 启动时会在 `deep_agent_namespace` 中查找或创建默认命名空间。`deep_agent_workspace` 保存归属命名空间、账号与会话，按这三个字段分别建立索引。新业务库由 [初始化 SQL](../../../../sql/init.sql) 建表。已有业务库缺少这两张表时，执行该脚本末尾的 DeepAgents 段落即可。该段落可以重复执行。

- 通过 `DeepAgentRuntimeService` 管理工作区生命周期（创建/清理/状态追踪）
- 命名空间（`deep_agent_namespace`）隔离不同业务线的 Agent 数据
- 工作区（`deep_agent_workspace`）映射账号→命名空间→会话→沙箱实例
- 运行时初始化采用 fail-closed 策略：工作区根目录、PostgreSQL 连接字符串、后端类型缺一不可
- 过期工作区按 `DeepAgentsCleanupIntervalSec` 配置定期清理（completed/cancelled 状态）

### Deep Agent 上下文持久化

- 对话上下文（checkpoints）通过 `PostgresSaver` 持久化到 PostgreSQL，支持中断/恢复
- Agent 跨线程共享数据（store）通过 `PostgresStore` 持久化到 PostgreSQL
- **复用 TypeORM 的 DataSource 连接**，无需额外配置连接字符串，直接复用 `.env` 中的数据库配置
- `DeepAgentRuntimeService.initialize()` 启动时自动调用 `checkpointer.setup()` 和 `store.start()` 创建 `langgraph_checkpoints`、`langgraph_blobs`、`langgraph_metadata`、`langgraph_store` 表
- 持久化使对话状态在服务重启后仍可恢复（基于 `thread_id`）

### 依赖服务

- `ChatRetrievalService`：向量检索，从 pgvector 查询相关文档片段
- `ChatLlmService`：LLM 调用，通过 LangChain 抽象层支持多模型
- `KnowledgeService`：知识库管理，文档上传/分片/向量化
- `DeepAgentRuntimeService`：Deep Agent 工作区管理与运行时初始化
- `DeepAgentService`：Deep Agent 业务编排（流式/同步对话、RAG Tool 注入）

## 配置项

| 配置键                     | 说明                    |
| -------------------------- | ----------------------- |
| `chat-llm.model`           | LLM 模型名称            |
| `chat-llm.apiKey`          | API 密钥                |
| `chat-llm.baseUrl`         | 兼容 OpenAI 的 API 地址 |
| `embedding.dimension`      | 向量维度                |
| `embedding.model`          | Embedding 模型          |
| `retrieval.topK`           | 检索返回片段数          |
| `retrieval.scoreThreshold` | 最低相关度阈值          |
