# 实现逻辑

## 运行配置

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `ServiceName`、`Port` | `gateway-service`、3100 | 网关名称和监听端口 |
| `GatewayUpstreamMode` | `static` | `static` 或 `registry` |
| `GatewaySystemUrl`、`GatewayMiddlewareUrl`、`GatewayRagUrl` | 本机 3200、3300、3400 | 静态模式使用 HTTP(S) origin |
| `RegistryUrl`、`ControlPlaneToken` | 部署提供 | 注册模式通过控制面读取实例 |
| `GatewayRegistrySyncMs` | 15000 | 实例同步间隔 |
| `GatewayRegistrySnapshotMs` | 45000 | 从上次成功同步起计算快照有效期 |
| `GatewayRegistryLeaseMs` | 180000 | 实例最近心跳的有效期，默认与注册中心的六个 30 秒心跳周期一致 |
| `GatewayConnectTimeoutMs` | 3000 | 上游连接超时 |
| `GatewayIdleTimeoutMs` | 60000 | 普通请求的上游空闲超时 |
| `GatewayStreamIdleTimeoutMs` | 180000 | 聊天流的上游空闲超时 |
| `GatewayMaxBodyBytes` | 106954752 | 单次请求体总大小 |
| `GatewayTrustedProxyIps` | 空 | 逗号分隔的可信入口 IP |
| `GatewayAllowedOrigins` | localhost 和 127.0.0.1 的 HTTP 5173、4173 端口 | 逗号分隔的前端 HTTP(S) origin，按协议、主机和端口匹配 |

在入口设置可信 IP 后，由入口覆盖 `X-Forwarded-For` 和 `X-Forwarded-Proto`。system-service 的 `TrustedProxyIps` 填网关出口地址，以保留登录日志中的客户端 IP 和 HTTPS 会话行为。

## 实例选择

注册模式以服务名索引快照，读取有效实例的 `host:port`。每次成功同步整体替换缓存，空快照同样生效。暂时无法同步时使用有效期内的快照，超过时限则对该入口返回 503。运维可通过滚动重启触发立即同步。系统和 RAG 服务按服务轮询。文件服务使用本地磁盘，检测到多于一个有效实例时返回 503。

## 转发与验证

网关为允许的来源返回带 Cookie 的 CORS 响应。浏览器的 `OPTIONS` 预检按实际请求方法和路径检查公开接口，允许 `Content-Type`，由网关直接返回。携带未准入 `Origin` 的请求在转发前返回 403。服务调用可以继续发送无 `Origin` 的请求。

网关一次请求选择一个上游，通过流传输请求体、下载和 SSE。客户端断开时结束所关联的上游连接。网关保留业务 Cookie，重建转发头，并用 SDK 的 W3C trace 串联网关和上游日志。文件 origin 由 middleware-service 的 `UploadPublicBaseUrl` 指定，默认本地示例在 `127.0.0.1:3300`，Web 使用 `localhost:5173`。

执行 `pnpm --filter gateway-service test` 验证本地可控上游的路径、流、Cookie、CORS 和实例选择。生产切流和回滚见 [部署与可观测性](../../../../docs/project/部署与可观测性.md)。
