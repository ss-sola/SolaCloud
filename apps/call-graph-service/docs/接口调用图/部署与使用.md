# 部署与使用

在能读取目标源码、运行项目开发环境的主机上部署一个 `call-graph-service` 实例。该服务使用 SolaCloud 共享会话，网关转发请求和实时事件。扫描在独立线程中读取 TypeScript 源码，点击“启动探针”才会运行项目入口。

1. 在 SolaCloud 根目录安装工作区依赖。使用与目标项目兼容的 Node.js（至少 24.16）。微助教按原项目要求安装依赖并准备开发配置。
2. 将本服务的 `.env.example` 复制为 `.env`。把 `SessionSecret`、`SessionRedisUrl`、`SessionCookieName` 和 `SessionKeyPrefix` 配成与 system-service 一致。服务自身无需业务数据库。
3. 确认调用图服务的操作系统账号可以读取目标项目。调试人员可直接在页面输入项目根目录的绝对路径。使用容器时，挂载源码、项目依赖和配置，并填写容器内的路径。
4. 已有系统库执行 SQL 补丁 `sql/patches/add-api-call-graph-menu.sql`，新库使用 `sql/init_data.sql`。菜单在“运行与审计”分组，排序紧随“集中日志查询”。默认授予系统管理员 `system:call-graph:debug`；已有会话可刷新权限或重新登录。
5. 启动共享会话服务、system-service、管理网关和前端，在 SolaCloud 根目录运行 `pnpm start:call-graph`。静态网关通过 `GatewayCallGraphUrl` 连接，默认端口为 3500。生产注册模式沿用 SDK 的 `NodeEnv=production`、`RegistryUrl` 与控制面配置。随服务部署 `dist/`、`runtime/` 和生产依赖。
6. 打开“接口调用图”，输入项目目录并启动探针。监听就绪后，使用 Apifox 或原客户端向**探针显示的端口**发送请求，沿用原接口的鉴权、参数及请求体。扫描目录并选择接口即可查看对应调用图与请求，同一会话中可直接切换接口。点击“停止探针”结束本次目标进程。

微助教以开发模式运行 `src/index.ts`，从自己的项目加载环境配置，会执行原应用的启动、后台任务注册和外部依赖初始化。选用专用的开发数据库和 Redis。目标项目的首个 HTTP 监听端口被占用时，探针会改用操作系统分配的空闲端口，页面显示实际端口。

目标进程在监听前退出时，页面显示退出码或信号，以及可以从启动输出中识别的原因。60 秒内没有监听 HTTP 端口时，页面提示启动超时，服务停止该探针和它启动的独立 Worker。可识别的原因包括依赖连接失败、缺少模块和配置校验失败。完整启动日志保留在服务终端。

校本后端自动选择 NestJS 策略。静态扫描可直接读取源码。使用实时探针前，在校本项目中运行其构建命令以生成与当前源码一致的 `dist/main.js` 和 source map，然后按「启动探针」。启动探针会执行目标应用的引导逻辑。

已有 SolaCloud 系统库再执行 `sql/patches/add-api-call-graph-probe-dictionary.sql`，为“字典管理”补齐 `system / api_call_graph_probe` 的两项配置。该补丁只添加缺少的条目。保存额度后，下次启动项目探针即可使用新值。

## BullMQ 异步任务

扫描接口时会检查项目的 `package.json`，识别直接启动项目内文件的 `node` 脚本，并从入口及其依赖确认 BullMQ 注册。NestJS 需要先构建。Koa 可使用 Node 直接支持的 JavaScript 或 TypeScript 入口。点击「启动探针」会同时启动识别出的独立 Worker，同进程 Worker 由目标应用自己启动。两端需要连接同一 Redis 和队列。停止探针会结束它启动的 HTTP 与 Worker 进程。

需要额外命令、参数、加载器或进程管理器的启动脚本不会自动执行。无法确认独立入口时，页面仍可启动和跟踪 HTTP 及其进程内的 Worker。

使用开发队列验证。已有消费者也会参与抢占任务，只有当前探针会话中的 Worker 可以回传执行链。当前入口是 `Queue.add()`。Worker 通过沙箱子进程运行处理文件时，图上可以看到 Worker 执行及结果，沙箱内部方法不采集。
