# 实现逻辑

## 1. 聚合入口

`RuntimePermissionService.getRuntimeByAccountId()` 负责运行时聚合，处理顺序如下：

- 校验账号存在且启用
- 查询账号绑定的启用角色
- 读取角色关联的启用权限码
- 读取启用菜单，并按菜单 `permissionCodes` 与账号权限交集过滤
- 使用 `MenuRouteUtil.buildTree(...)` 组装树形结果，并通过 `MenuRouteUtil.toRuntimeTree(...)` 移除菜单节点上的 `permissionCodes` 输出字段

## 2. 菜单过滤规则

当前实现中，菜单满足以下任一条件即可进入候选集：

- 菜单未配置 `permissionCodes`
- 菜单配置的权限码与账号权限集合存在交集

命中子菜单后，会自动把祖先节点一并补回，保证前端可直接渲染完整树结构。

## 3. 权限校验接口

`checkPermissions()` 会对传入权限码去重、裁剪空值，再返回是否允许以及缺失权限码列表，供前端或其他服务做显式判断。

## 4. 缓存与失效

当前实现使用服务内 `Map<number, AccountRuntimePermission>` 做账号维度缓存。

- 缓存键：`accountId`
- 缓存内容：账号基础信息、角色编码、权限码、运行时菜单树
- TTL：当前未设置独立 TTL，缓存生命周期跟随服务进程
- 失效方式：
  - 账号更新
  - 账号删除
  - 密码重置
  - 账号角色绑定保存
  - 管理页手动刷新
- 降级策略：当缓存未命中时重新从数据库聚合运行时权限；服务进程重启后自动清空缓存并重新构建

当前还没有把角色、权限、菜单变更统一联动到该缓存，这部分仍属于第一阶段后续收口项。
