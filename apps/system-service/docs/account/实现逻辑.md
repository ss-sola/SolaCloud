# 实现逻辑

## 1. 初始化管理员

`AccountService.onModuleInit()` 会检查默认管理员是否存在。若不存在，则使用 `DEFAULT_ADMIN_ACCOUNT` 自动补齐初始账号，后续不会覆盖用户修改。

默认管理员密码不再写死在代码里。首次初始化时必须通过 `DefaultAdminPassword` 配置提供密码；未配置时服务只记录警告并跳过默认管理员创建。

## 2. 账号保存与状态版

`AccountService` 负责账号新增、更新、删除。账号头像使用可选 `avatarUrl` 字段保存，写入时会去除首尾空白，空字符串归一为空值；账号详情、列表和登录 session 主体都会返回该字段。账号表不保存文件 ID，头像文件侧通过 `businessType=account-avatar` 保留上传归属数据。

账号基础信息更新后会触发对应账号运行时权限缓存失效，但不递增 `statusVersion`，当前登录态可继续刷新使用。只有密码重置、登录锁定等安全状态变化才递增 `statusVersion`，让旧 session 失效。

## 3. 密码与安全状态

密码摘要统一通过 `PasswordUtil` 处理，不在模块内保存明文。密码重置时会同步：

- 更新 `passwordHash`
- 清零 `failedLoginCount`
- 清空 `lockedUntil`
- 递增 `statusVersion`
- 写入操作日志与登录日志

## 4. 统一账号主体

前台用户和后台管理用户都使用 `account` 作为登录主体。登录态、权限聚合、通知、审计等运行时链路统一使用 `accountId`，不再引入独立 `userId` 主体。

## 5. 账号角色绑定

角色绑定对外只接收 `roleCodes`。`AccountService.saveRoleCodes()` 会先校验角色是否存在且启用，再用 `sys_account_role` 全量替换账号角色集合。

历史 `sys_user`、`sys_user_identity`、`sys_user_role` 已不再作为运行时主体表使用，当前本地库在确认 0 行、无外键依赖、无活跃代码引用后已清理。后续账号主体关系只维护 `sys_account` 与 `sys_account_role`。

## 6. 表结构注释

账号相关实体字段通过 TypeORM `comment` 元数据维护中文注释，初始化脚本 `sql/system-service.sql` 与现有库补丁脚本 `sql/patches/system-service-field-comments.sql` 同步维护 `COMMENT ON TABLE` / `COMMENT ON COLUMN`。公共审计字段注释由 `NestCloud-Sdk` 的 `BaseEntity` 统一承载。

## 7. 头像上传接入

账号总览接口返回 `avatarUpload` 配置，前端账号弹窗使用该配置上传头像文件。上传请求字段包含 `file`、`scene`、`businessType=account-avatar` 与 `isTemporary=false`；上传成功后将返回的 `url` 写入现有 `avatarUrl` 输入框，再通过账号新增或更新接口保存。

`AccountAvatarUploadUrl` 和 `AccountAvatarUploadScene` 可通过配置覆盖，默认分别为 `http://localhost:3300/api/file/upload` 与 `account`。

## 8. 日志、分页与缓存联动

当前已接入以下联动：

- 账号新增、更新、删除、密码重置、角色绑定写入操作日志
- 登录失败、登录成功、锁定、登出、密码重置写入登录日志
- 账号更新、删除、密码重置、角色绑定后失效对应账号运行时权限缓存
- 角色权限变更后通过 `SessionPermissionService` 直接查询角色仓储维护角色账号索引，不再反向依赖 `RoleService`，避免权限链路出现循环注入导致服务启动失败
- 账号列表会批量读取当前页账号的角色编码，避免分页列表对每行重复查询角色关系

## 9. 跨模块账号选项接口

账号模块额外提供 `GET /api/system/accounts/options` 轻量接口，专门服务通知等跨模块选择场景。该接口只返回启用账号的 `id`、`accountName`、`displayName` 三个字段，不复用带分页和管理字段的账号列表接口。

控制器使用 `RequireAnyPermissions(SYSTEM_PERMISSION_CODES.accountManage, SYSTEM_PERMISSION_CODES.notificationManage)` 放行账号管理或通知管理任一权限，保持资源归属模块提供选择项的同时，不增加通知模块自己的重复接口。
