# 实现逻辑

## 分层职责

- `controller`：接收查询参数与请求体，并统一包装响应；资源标识统一通过 query 参数传递。
- `service`：承载命名空间管理、字典管理、字典项查询 / upsert / 删除、批量导入与默认初始化。
- `entity`：声明 `sys_dict_namespace`、`sys_dict_aggregate` 与 `sys_dict_item` 表结构。
- `form`：使用 `class-validator` 做参数校验。
- `util`：承载无状态辅助逻辑，例如必填项断言、导入项转换与去重归一化。

## 核心流程

### 1. 命名空间流程

- `listNamespaces()`：返回命名空间元信息，并结合字典与字典项汇总条数和最近更新时间。
- `getNamespace(namespace)`：按 namespace 返回单个命名空间元信息，不存在时抛出异常。
- `upsertNamespace(namespace, payload)`：按 namespace 幂等保存命名空间元信息，并写入操作日志。
- `removeNamespace(namespace)`：仅删除空命名空间；若仍存在字典则抛出业务异常，避免隐式级联删除。

### 2. 字典流程

- `listAggregates(query)`：按 namespace 查询字典列表，支持关键词、启停状态、分页和排序。
- `getAggregate(namespace, aggregateKey)`：按 `namespace + aggregateKey` 查询单个字典，不存在时抛出异常。
- `upsertAggregate(namespace, aggregateKey, payload)`：确保命名空间存在后幂等保存字典元信息，并写入操作日志。
- `removeAggregate(namespace, aggregateKey)`：仅删除空字典；若字典下仍有字典项则抛出业务异常。

### 3. 字典项查询流程

- `listItems(query)`：按 `namespace + aggregateKey` 查询字典项并返回完整列表；若传入 `keys`，则仅返回命中的字典项，并继续支持按 `key / updatedAt` 等允许字段排序。
- `getItem(namespace, aggregateKey, key)`：按 `namespace + aggregateKey + key` 查询单项，不存在时抛出 `ProjectException`。

### 4. 运行态查询流程

- `listRuntimeItems(query)`：按 `namespace + aggregateKey` 和可选 keys 查询运行态字典项。
- 运行态只返回启用命名空间、启用字典下的启用字典项，不写操作日志。
- 命名空间不存在、命名空间停用、字典不存在或字典停用时返回空列表，前端可使用原始值降级。
- 运行态接口用于页面下拉选项和展示文案，不替代系统参数值类型、编号规则周期等业务校验常量。

### 5. 写入流程

- `upsertItem(namespace, aggregateKey, key, payload)`：
  1. 校验 `namespace`、`aggregateKey`、`key`。
  2. 确保命名空间存在，不存在时自动补建最小记录。
  3. 确保字典存在，不存在时自动补建最小记录。
  4. 查询当前记录是否存在。
  5. 合并新旧字段并归一化可选字符串与启停状态。
  6. 保存前通过共享基础服务写入 `create_user` / `update_user` 审计字段。
  7. 保存后重新查询字典项，再返回包含 `createdAt` / `updatedAt` 等生成字段的完整记录。
  8. 写入操作日志。

### 6. 删除流程

- `removeItem(namespace, aggregateKey, key)`：查询目标记录，不存在则抛异常，存在则删除并写入操作日志。
- `removeAggregate(namespace, aggregateKey)`：查询字典，不存在则抛异常；删除前统计字典下字典项数量，非空时拒绝删除。
- `removeNamespace(namespace)`：查询命名空间，不存在则抛异常；删除前统计命名空间下字典数量，非空时拒绝删除。

### 7. 导入流程

- `importNamespace(namespace, items, options?)`：
  1. 先补齐命名空间元信息。
  2. 调用 `DictionaryUtil.normalizeImportItems(...)` 做 trim、去空、去重。
  3. 导入项必须显式包含 `aggregateKey`。
  4. 同一次导入按 `aggregateKey + key` 去重。
  5. 每个合法项最终都走 `upsertItem(...)`。
  6. 返回 created / updated / skipped 摘要。
  7. 写入操作日志。

### 8. 默认初始化流程

- `onModuleInit()` 先执行旧前缀 key 迁移，再调用 `ensureSeedData()`。
- 旧数据若缺少 `aggregateKey`，会按最后一个 `.` 拆分为 `aggregateKey + key`；无 `.` 的 key 进入 `_ungrouped` 字典。
- 默认初始化按 namespace 确保命名空间存在，再按 aggregate 确保字典存在，最后按 key 检查缺失项。
- 初始化只补齐缺失字典项，不覆盖已有 `value / label / description / isEnabled`。
- 默认数据覆盖通用启停、成功状态、系统参数值类型、编号规则周期、日志、权限分组、通知状态等展示字典。
- 推荐枚举状态默认集中写入 `common` 命名空间，通过字典拆分为多个选项组。
