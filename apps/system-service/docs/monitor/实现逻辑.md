# 实现逻辑

## 1. 在线用户注册表

`OnlineUserService` 使用进程内 `Map<sessionId, OnlineUserRecord>` 保存当前实例观察到的在线会话。

写入来源：

- 登录成功后，`AuthController.login()` 使用当前 `sessionID` 写入在线用户
- 登出时，`AuthController.logout()` 按 `sessionID` 删除在线用户
- 当前账号中间件校验 session 成功后，刷新对应会话的 `lastActiveAt`、IP、User-Agent 与过期时间

## 2. 过期清理

在线用户记录的过期时间基于 session TTL 计算：

- TTL 读取 `SystemConfigKeys.SessionTtlMs`
- 未配置时使用账号模块默认 session TTL
- 查询总览或列表时会先清理已过期记录

当前实现不扫描 Redis session，也不跨实例同步在线用户，因此多实例部署时只反映当前进程观察到的在线会话。

## 3. 踢人下线

踢人下线通过 `OnlineUserService.kickOffline()` 编排：

1. 先清理过期在线记录
2. 拒绝踢出当前操作者自己的 session
3. 校验目标 `sessionId` 是否仍在在线用户注册表中
4. 通过 `OnlineUserSessionService.destroyBySessionId()` 销毁 Redis session
5. session 销毁成功后，再从在线用户 Map 中移除目标记录

`OnlineUserSessionService` 复用 NestCloud-Sdk 的 `RedisSessionStore.destroy(sessionId)`，按系统配置中的 `SessionRedisUrl`、`SessionKeyPrefix` 定位并删除 session key。未配置 Redis session 时，运行时会降级为 MemoryStore；该模式下业务服务无法主动删除任意其他会话，因此踢人下线接口会返回明确业务异常。

## 4. 在线用户查询

`OnlineUserQueryForm` 继承分页入参约定，字段为 `pageNum`、`pageSize`，并增加可选 `keyword`。

查询流程：

1. 清理过期记录
2. 按账号名、展示名、IP、User-Agent 做关键词过滤
3. 按 `lastActiveAt` 倒序排序
4. 使用 `PaginationUtil.paginateArray()` 与 `PaginationUtil.buildPageResult()` 返回分页结果

## 5. 服务指标采集

`ServiceMonitorService.getServiceMetrics()` 使用 Node 内置能力采集：

- `os.cpus()`：CPU 型号和核心数
- `os.loadavg()`：系统负载
- `os.uptime()`：系统运行时长
- `os.totalmem()` / `os.freemem()`：系统内存
- `process.memoryUsage()`：当前 Node 进程内存
- `fs.promises.statfs()`：当前服务工作目录所在磁盘空间
- `os.hostname()` / `os.platform()` / `os.arch()` / `os.release()`：服务器信息

磁盘采集失败不会影响其他指标返回，会降级为 `available=false` 并携带错误说明。

## 6. 访问控制

监控接口统一使用 `SessionAuthGuard` 与 `PermissionGuard`：

- 总览接口允许在线用户监控查询权限或服务监控查询权限任一满足
- 在线用户列表要求 `system:monitor:online-user:query`
- 在线用户踢人下线要求 `system:monitor:online-user:kick`
- 服务监控要求 `system:monitor:service:query`
