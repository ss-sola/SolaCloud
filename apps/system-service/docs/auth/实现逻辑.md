# 实现逻辑

## 1. Session 中间件接入

`main.ts` 启动时通过 `createRedisSession(...)` 注入 session 中间件。配置值统一由 `ConfigKey + getConfig + validate.config.ts` 读取，不在业务代码里直接读取环境变量。

部署通过 `SessionSecret` 提供非空的会话签名密钥。共享登录态的进程使用相同的密钥、Redis 地址和会话前缀。

## 2. 登录校验

前台用户和后台管理用户都使用 `account` 登录，`AccountService.login()` 负责：

- 校验账号是否存在
- 校验账号是否启用
- 校验是否处于锁定期
- 校验密码摘要
- 登录成功后清零失败次数、更新最近登录时间并返回 session 主体

## 3. 登录失败与锁定

当密码校验失败时，服务会累计 `failedLoginCount`。达到上限后写入 `lockedUntil`，并递增 `statusVersion`，让旧会话在后续校验时失效。

## 4. 会话刷新与登出

- `refreshSession()` 会重新校验当前账号状态，并保留原始 `loginAt`
- `logout()` 会记录一条登出安全事件，再由控制器销毁 session
- `validateSession()` 会校验 `accountId`、`isEnabled` 与 `statusVersion`
- 会话主体输出 `accountId`、账号名、展示名、头像 URL、状态版本与登录时间，不再维护独立 `userId` 登录主体

## 5. 当前账号注入

`createRedisSession(...)` 注入 session 中间件后，系统会继续注册当前账号注入中间件。该中间件读取 `req.session.account`，调用 `AccountService.validateSession()` 校验账号状态，并把通过校验的账号挂到 `req.currentAccount`。

注入中间件不负责拒绝请求：无 session 或 session 失效时只保持 `req.currentAccount` 为空，后续由 Guard 决定是否拦截。

## 6. 管理接口访问边界

管理类 controller 统一接入 `SessionAuthGuard` 与 `PermissionGuard`：

- `SessionAuthGuard` 只从 `req.session.account` 判断是否存在登录态，不写入 `req.currentAccount`
- `@RequirePermissions(...)` 声明接口所需权限码，默认要求全部权限满足
- `@RequireAnyPermissions(...)` 声明任一权限满足即可访问，适用于 options / lookup 这类跨模块选择项接口
- `PermissionGuard` 读取方法或 controller 上声明的权限码，基于中间件注入的 `req.currentAccount.id` 调用 `RuntimePermissionService.checkPermissions()` 判断当前账号是否具备权限
- 未声明权限码的接口只校验登录态，适用于当前账号运行态公告、站内信等个人入口

`AuthController.login` 保持公开入口；`current`、`refresh` 继续通过 `AccountService` 的 session 校验逻辑返回当前会话。登录成功和登出时会同步维护在线用户注册表，当前账号中间件在校验通过后刷新在线用户最近活跃时间。
