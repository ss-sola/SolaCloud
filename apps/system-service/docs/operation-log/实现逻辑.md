# 实现逻辑

## 分层职责

- `controller`：负责接收查询参数并包装响应
- `service`：负责日志写入、列表查询与总览统计
- `entity`：声明 `sys_operation_log` 表结构
- `form`：通过 `class-validator` 校验查询参数

## 核心流程

### 1. 日志写入流程

- 业务模块调用 `OperationLogService.log(payload)`
- 服务会对 `module`、`action`、`targetType`、`summary` 等字段进行最小归一化
- 保存成功后返回标准日志记录结构

### 2. 日志查询流程

- `listItems(query)` 会按 `module`、`action`、`targetType`、`operator` 下推数据库过滤
- 结果按 `id DESC` 排序，优先返回最新日志

### 3. 模块接入范围

当前已接入以下模块写操作日志：

- dictionary
- menu-route
- permission
- role

## 设计约束

- 仅保留最小必要字段，避免进入复杂审计平台路线
- 只提供查，不提供改
- logger 继续保留，操作日志作为更稳定的数据化留痕补充
