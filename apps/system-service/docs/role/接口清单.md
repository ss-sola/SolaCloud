# 接口清单

## 路由前缀

- 全局前缀：`/api`
- 模块前缀：`/system/roles`

## 接口列表

- `GET /api/system/roles/overview`：获取模块总览
- `GET /api/system/roles`：按条件查询角色列表
- `GET /api/system/roles/options`：查询启用角色选项，用于账号角色绑定等跨模块选择场景
- `GET /api/system/roles/item?id=...`：查询单个角色
- `GET /api/system/roles/runtime?roleCode=...`：查询角色运行态预览
- `POST /api/system/roles`：创建角色
- `PUT /api/system/roles/item?id=...`：更新角色
- `DELETE /api/system/roles/item?id=...`：删除角色

## 角色选项返回结构

`GET /api/system/roles/options` 只返回启用角色的最小选择字段，不返回权限绑定、描述、时间等管理字段。

```json
[
  {
    "code": "system-admin",
    "name": "系统管理员"
  }
]
```

该接口允许角色管理权限或账号管理权限访问，避免账号页绑定角色时复用完整角色管理列表接口。

## 创建/更新请求结构

```json
{
  "code": "system-admin",
  "name": "系统管理员",
  "description": "默认系统管理员角色",
  "isEnabled": true,
  "permissionCodes": ["system:dictionary:manage", "system:menu-route:manage"]
}
```

## 运行态返回结构

```json
{
  "roleCode": "system-admin",
  "menuTree": [],
  "permissionCodes": ["system:dictionary:manage"]
}
```

## 查询与写入规则

- 资源标识统一通过 query 参数传递
- `code`、`name` 必填，最大长度 64
- `description` 可选，最大长度 255
- `permissionCodes` 为可选字符串数组，使用权限码而不是权限 ID
- 服务端会先校验权限码是否存在且启用，再映射为 `sys_role_permission.permissionId` 持久化
- 角色接口不再接收或返回 `menuRouteIds`、`userIds`
- 运行态 `menuTree` 由角色当前权限码与菜单上的 `permissionCodes` 交集反推
- 若命中的菜单存在父节点，父节点会一并补齐，以保证树结构完整
