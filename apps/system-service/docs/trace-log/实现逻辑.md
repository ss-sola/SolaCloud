# 集中日志查询实现

system-service 通过固定的 Loki 查询端点查询最近 24 小时的日志。每次列表查询和原文加载都验证账号当前状态、会话版本及最新有效权限。查询覆盖指定 `job` 下的所有服务实例，使用结构化元数据 `trace_id` 精确匹配。请求共享 5 秒查询时限。

列表使用 Loki 的行投影提取前 1200 个 Unicode 码位。超过 500 条时，单独检索入口网关及服务完成和异常记录，各取最多 64 条，再用较早的普通日志补至 500 条。原文请求按同一 trace、精确时间戳、服务及实例定位并验证预览标识。原文响应上限为 256 KiB。

Alloy 为每个日志流设置 `job`、`service` 和 `instance`。实例地址优先采用 `instance_address` 标签。沿用本机采集配置时，后端可解析 `<service>-<host>-<port>` 形式的实例标识。

system-service 在匹配业务路由的响应发出后记录一次 INFO 请求完成日志，覆盖正常响应、缓存校验的 304 和错误响应。日志沿用 SDK 的 traceId 和 spanId，正文包含请求方法、路由模板、实际 HTTP 状态码、开始时间 `startedAtMs` 和耗时。查询参数、请求正文和 Cookie 不写入这条请求日志。抛异常时 SDK 另行记录异常和堆栈。

| system-service 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `TraceLogLokiUrl` | 空 | Loki 的内部 HTTP(S) 地址。本机示例为 `http://127.0.0.1:3101`。留空时关闭查询 |
| `TraceLogLokiJob` | `solacloud-local` | 与 Alloy 采集端的 `job` 标签一致 |

现有数据库执行 `sql/patches/add-trace-log-menu.sql` 添加菜单和权限。新建数据库由 `sql/init_data.sql` 初始化。首次安装要求默认审计分组和系统管理员角色可用，并将权限授予 `system-admin`。重跑补丁保留管理员后来调整的授权。权限变更后可刷新登录权限以更新已打开页面的菜单。
