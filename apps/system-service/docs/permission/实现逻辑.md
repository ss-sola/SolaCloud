# 实现逻辑

## 分层职责

- `controller`：接收 query 和 body，并统一包装响应
- `service`：承载权限码查询、写入、删除、种子初始化与日志写入
- `entity`：声明 `sys_permission` 表结构
- `form`：通过 `class-validator` 校验查询与保存参数

## 核心流程

### 1. 查询流程

- `listItems(query)`：先按 `groupKey`、`isEnabled` 下推数据库过滤，再按 `keyword` 做轻量补充筛选
- `getItem(id)`：按 ID 查询单项，不存在直接抛出 `ProjectException`

### 2. 写入流程

- `createItem(payload)`：校验 `code` 唯一后保存，并写入操作日志
- `updateItem(id, payload)`：先校验记录存在，再校验 `code` 唯一性，保存后写入操作日志
- `removeItem(id)`：删除记录并写入操作日志
- 权限新增、更新、删除后都会调用 `RuntimePermissionService.invalidateAll()`，避免角色菜单过滤继续使用旧权限码

### 3. 种子初始化流程

- `onModuleInit()` 调用 `ensureSeedData()`
- 对默认权限码按 `code` 补齐缺失项，不覆盖现有业务数据
- 默认权限码按业务类型写入 `groupKey`：`platform` 表示平台入口，`resource` 表示基础资源，`identity` 表示身份权限，`audit` 表示审计日志
- 已存在的默认权限码会同步最新 `groupKey`，但不会覆盖 `name`、`description`、`isEnabled` 等可维护字段
- 默认权限码覆盖字典、菜单、权限、角色、操作日志等基础模块

### 4. 菜单联动规则

- `PermissionService.assertCodesExist()` 会校验权限码存在且处于启用状态
- `MenuRouteService` 在创建和更新菜单时都会调用该校验方法
