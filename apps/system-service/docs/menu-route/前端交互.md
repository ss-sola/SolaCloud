# 前端交互

## 访问入口

- `NestCloudWeb` 页面入口：`/system/menu-route`
- 页面宿主：`web/NestCloudWeb/src/modules/system/pages/LegacySystemConsolePage.tsx`
- 菜单管理实现：`web/NestCloudWeb/src/modules/system/legacy/menu-route-page.js`

## 页面职责

菜单路由管理页负责把 `menu-route` 后端接口组织成可直接操作的后台管理界面，并维护当前运行时菜单树，覆盖以下能力：

- 查看模块总览
- 按条件查询菜单列表
- 查看菜单树摘要
- 新增 / 编辑菜单路由
- 删除菜单路由
- 批量启用 / 停用菜单
- 同页调整排序并立即生效
- 维护菜单与权限码的绑定关系

## 对接接口

- `GET /api/system/menu-routes/overview`
- `GET /api/system/menu-routes`
- `GET /api/system/menu-routes/tree`
- `GET /api/system/menu-routes/item?id=...`
- `GET /api/system/permissions`
- `POST /api/system/menu-routes`
- `PUT /api/system/menu-routes/item?id=...`
- `PUT /api/system/menu-routes/batch-status`
- `PUT /api/system/menu-routes/reorder`
- `DELETE /api/system/menu-routes/item?id=...`
- `GET /api/system/runtime-permissions/current`

## 页面交互说明

### 1. 列表与树查询

- 页面初始化时同时拉取总览、平铺列表、树结构与权限码列表。
- 查询区支持：`keyword`、`parentId`、`isEnabled`。
- `parentId` 在筛选区和编辑弹窗中都使用树形下拉，层级顺序复用当前菜单树展开结果。
- 左侧导航仅展示 `isEnabled = true` 且 `isHidden = false` 的节点；`meta.group = true` 的节点渲染为分组标题。
- 前端使用运行时菜单的 `routeName` 查找路由注册表中的页面。

### 2. 新增 / 编辑

- 新增与编辑共用同一个 modal。
- 编辑前先调用 `GET /item?id=...` 回填表单。
- `code` 只在新增时填写；编辑已有菜单时输入框只读，更新接口也不再接收 `code`。
- `parentId` 下拉会自动过滤当前节点和其全部子孙节点，避免形成闭环。
- `component` 保存页面组件标识，例如 `dictionary`、`menu-route`。
- `icon` 只保存 SVG 名称，例如 `dictionary`、`system-access-group`；前端再尝试解析到 `public/assert/svg/**`，解析不到时允许纯文本回退。
- `meta` 输入区支持 JSON 文本，为空时不提交；当前常见键为 `group` 与 `routeRoot`。
- 菜单保存成功后会联动刷新列表、树结构与左侧导航。

### 3. 批量启停、排序调整与删除

- 列表首列支持勾选，页面提供“批量启用 / 批量停用”按钮。
- 批量启停成功后，会刷新列表、树结构与左侧导航。
- `sort` 列支持直接修改数字输入框，并通过“应用排序”统一提交。
- 排序提交按当前页面中的 `id + sort` 一次性发送到 `PUT /reorder`。
- 删除前弹出浏览器确认框；删除成功后刷新总览、列表与树结构。
- 若后端因子节点未清空而拒绝删除，页面直接展示接口错误。

## 手工验证清单

- 打开 `/system/menu-route`。
- 确认总览、列表与树摘要可以正常加载。
- 使用 `keyword`、`parentId`、`isEnabled` 过滤并确认结果一致。
- 编辑已有菜单并确认 `code` 只读、`parentId` 为树形下拉、`icon` 与 `component` 可正确回填。
- 修改某个菜单的 `path` 或 `meta.routeRoot` 后，确认前端地址与页面绑定一并更新。
- 批量启停、排序调整、删除后确认左侧导航同步刷新。
- 新增 / 编辑菜单时确认权限码可按关键词、分组、启用状态筛选，并可全选或清空当前筛选。
- `meta` 输入非法 JSON 时页面应阻止提交并提示错误。
