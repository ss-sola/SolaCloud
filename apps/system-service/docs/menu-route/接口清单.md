# 接口清单

## 路由前缀

- 全局前缀：`/api`
- 模块前缀：`/system/menu-routes`

## 接口列表

- `GET /api/system/menu-routes/overview`：获取模块总览
- `GET /api/system/menu-routes`：按条件查询菜单列表
- `GET /api/system/menu-routes/tree`：查询菜单树
- `GET /api/system/menu-routes/item?id=...`：查询单个菜单
- `POST /api/system/menu-routes`：创建菜单
- `PUT /api/system/menu-routes/item?id=...`：更新菜单
- `PUT /api/system/menu-routes/batch-status`：批量更新菜单启停状态
- `PUT /api/system/menu-routes/reorder`：批量调整菜单排序
- `DELETE /api/system/menu-routes/item?id=...`：删除菜单

## 创建请求结构

```json
{
  "code": "dictionary-management",
  "name": "字典管理",
  "path": "dictionary",
  "parentId": 19,
  "component": "dictionary",
  "redirect": null,
  "icon": "dictionary",
  "sort": 2,
  "isEnabled": true,
  "isHidden": false,
  "permissionCodes": ["system:dictionary:manage"],
  "meta": null
}
```

## 查询与写入规则

- 所有资源标识统一通过 query 参数传递，不使用 RESTful 路径参数。
- 列表、树查询与单项查询响应中均返回 `component`、`icon`，不再返回 `routeName`。
- 创建接口要求 `code`、`name`、`path` 必填；更新接口不允许修改 `code`。
- `code` 在服务内唯一。
- `parentId` 不能指向自身，也不能形成祖先-后代闭环。
- `meta.group = true` 的分组节点允许 `component` 为空；可直接打开的叶子菜单应补齐 `component`。
- `icon` 只保存 SVG 名称，不保存完整文件路径。
- 删除前必须保证当前菜单没有子节点。
- `permissionCodes` 会在写入前去重并去除空白项。
- `permissionCodes` 保存前会校验权限码是否存在且启用。
- 默认菜单种子包含 1 个系统管理根节点、4 个分组和 13 个系统管理叶子入口。
