# 实现逻辑

## 1. 公告发布与撤回

`NotificationService.saveAnnouncement()` 统一处理公告新增与更新：

- `effectiveFrom`、`effectiveTo` 会先转成 `Date`
- 如果开始时间晚于结束时间，直接抛错
- `isPublished=true` 时会补齐首次 `publishedAt`
- 撤回时记录 `revokedAt`
- 已撤回公告再次发布时会清空 `revokedAt`
- 发布请求如果带有 session 账号，会把 `publisherAccountId` 写入公告记录

## 2. 公告运行态过滤

`listRuntimeAnnouncements()` 只返回满足以下条件的公告：

- `isPublished=true`
- 当前时间位于 `effectiveFrom ~ effectiveTo` 之间
- `revokedAt` 为空

过滤条件会尽量下推到数据库查询，管理态可以保留草稿和历史撤回记录，运行态只暴露真正生效的公告。

## 3. 站内信发送策略

`sendMessages()` 支持两种发送模式：

- 定向发送：对 `receiverAccountIds` 去重后批量写入 `sys_station_message`
- 广播发送：读取全部启用账号，按账号批量落库

发送请求如果来自已登录后台账号，会把 `senderAccountId` 一并写入消息记录。

## 4. 已读状态处理

- `markRead()` 必须同时匹配消息 ID 与当前接收账号，避免只凭消息 ID 标记他人站内信
- `markRead()` 对单条消息做幂等更新，已有 `readAt` 时不会重复覆盖
- `markAllRead()` 按当前账号批量处理全部未读消息，并返回本次更新数量
- `unreadCount()` 直接按 `receiverAccountId + isRead=false` 统计未读数

## 5. 运行态站内信预览

`listRuntimeMessages()` 复用站内信查询逻辑，只按当前 session 账号返回消息列表。运行态接口不再接受调用方传入 `receiverAccountId` 预览其他账号消息。
当前管理页会同时展示：

- 当前运行中的公告
- 当前登录账号的运行态站内信列表
- 当前登录账号的未读数
