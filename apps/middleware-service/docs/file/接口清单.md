# 接口清单

## POST /file/upload/check

检查或创建分片上传状态。

Body JSON 字段：

- `fileId`：前端基于“前端会话 id + ':' + sourceHash”计算出的上传会话标识。
- `totalSize`：文件总字节数。
- `chunkSize`：单个分片字节数。
- `chunkCount`：总分片数。
- `sourceHash`：基于文件源信息计算的 `SHA-256`，用于稳定标识“同一个源文件”，并参与前端 `fileId` 计算。

返回字段：

- `fileId`：上传会话标识；服务端会校验它与 `sourceHash` 匹配，并在整个 `check / upload / merge` 过程中复用。
- `uploadId`：内部上传会话 ID，用于磁盘临时目录和审计。
- `status`：会话状态。
- `totalSize`
- `uploadedBytes`
- `chunkSize`
- `chunkCount`
- `uploadedChunkCount`
- `uploadedChunkIndexes`
- `percent`
- `canMerge`
- `mergedFileId`：可选，已合并完成时返回最终文件 ID。
- `errorMessage`：可选，最近一次失败原因。

补充说明：

- 服务端会优先返回磁盘真实已落盘的分片索引，而不是只信任历史计数。
- 同一 `fileId` 如果已绑定不同的分片配置，会返回 `409` 冲突错误。
- 文件名、MIME、业务场景和临时标记不再在 `check` 阶段传递，而是在 `merge` 阶段提交。

## POST /file/upload

上传单个分片，文件字段名固定为 `file`，请求类型为 `multipart/form-data`。

Body 表单字段：

- `file`：当前分片文件。
- `fileId`：来自 `check` 返回的上传会话标识。
- `chunkIndex`：当前分片序号，从 `0` 开始。
- `chunkHash`：可选，当前分片内容哈希；当前服务端仅接收并透传，不作为强校验条件。

返回：当前上传会话进度快照，字段与 `check` 的返回结构一致，重点包括 `uploadedChunkIndexes`、`uploadedBytes`、`percent` 和 `canMerge`。

补充说明：

- 重复上传同一分片不会重复累计，服务端会按真实分片快照修正进度。
- 如果分片序号不合法，或分片大小与当前会话约定不一致，会直接拒绝请求。

## POST /file/upload/merge

在全部分片上传完成后执行顺序合并，生成正式文件元数据。

Body JSON 字段：

- `fileId`：来自 `check` 返回的上传会话标识。
- `fileHash`：前端对整文件内容增量计算出的 `SHA-256`。
- `originalName`：最终保存时使用的原始文件名。
- `mimeType`：可选，最终保存时使用的 MIME；缺省时回退为 `application/octet-stream`。
- `scene`：可选，业务场景。
- `businessType`：可选，业务类型；账号头像上传使用 `account-avatar`。
- `isTemporary`：可选，是否临时文件，默认 `true`。

返回：上传会话最终进度快照，以及最终文件记录 `file`。

`file` 结构包含：

- `id`
- `originalName`
- `storageKey`
- `storagePath`
- `url`
- `previewUrl`
- `mimeType`
- `size`
- `extension`
- `scene`
- `businessType`
- `isTemporary`
- `status`
- `createdAt`
- `updatedAt`

补充说明：

- 服务端在合并后会重新流式计算正式文件的 `SHA-256`，与 `fileHash` 一致才会落库。
- 服务端会使用 merge 请求体中的文件名、类型和业务语义来创建最终 `middleware_file_item` 记录。
- 合并期间会持有 Redis merge 锁，防止重复并发合并。
- 哈希不一致时会删除半成品正式文件，并把上传会话标记为失败，便于后续重新对账或重试。

## GET /file/list

分页查询文件列表。

Query 参数：

- `pageNum`：页码。
- `pageSize`：每页数量。
- `scene`：可选场景。
- `businessType`：可选业务类型。
- `status`：可选状态。
- `isTemporary`：可选是否临时文件。

分页返回数组字段统一为 `list`。

## GET /file/detail

Query 参数：

- `id`：文件 id。

## POST /file/batch-detail

Body 为 `{ "ids": [1, 2] }`。`ids` 至少包含一个正整数，各 ID 唯一。响应的 `data` 为匹配的文件详情数组。此接口只查询数据，RAG 客户端可在瞬时网络故障后重试。

## PUT /file/description

Body 为 `{ "id": 1, "description": "附件描述" }`。`id` 为正整数，`description` 为字符串，传空字符串可清空描述。成功时返回 `{ "data": true, "message": "ok", "code": 200 }`。

客户端通过 `Idempotency-Key` 标记一次逻辑写入的所有重试。更新描述沿用原有公开权限，每个键绑定首次调用的身份和参数。相同身份与参数回放已提交的结果。同键搭配不同文件 ID、描述或身份（包括登录会话过期）返回 HTTP 409。调用方应为独立写入生成新键。无键的兼容请求仍按次更新。

## DELETE /file/remove

Query 参数：

- `id`：文件 id。

删除元数据并尝试删除物理文件。
