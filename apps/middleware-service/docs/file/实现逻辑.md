# 实现逻辑

## `check`：检查或创建上传状态

1. Controller 接收 `FileUploadCheckForm`，清洗 `fileId` 与 `sourceHash`，并保留 `totalSize / chunkSize / chunkCount` 作为分片规则校验参数。
2. `FileUploadSessionService` 先校验 `totalSize / chunkSize / chunkCount` 之间的几何关系是否合法。
3. 服务端校验前端传入的 `fileId` 是否以 `':' + sourceHash` 结尾，从而确认它与“前端会话 id + sourceHash”的协议一致。
4. 先尝试读取 Redis 快照，再回退到数据库中的 `middleware_file_upload_session`，查找同一 `fileId` 下尚未完成、未过期且不在合并中的活动会话。
5. 若已存在活动会话：
   - 校验分片配置是否一致。
   - 基于磁盘分片目录重新构建 `uploadedChunkIndexes`、`uploadedBytes` 和 `uploadedChunkCount`，刷新会话状态与过期时间。
6. 若不存在活动会话：
   - 生成新的 `uploadId`。
   - 创建上传会话记录，保存相对 `chunkDirPath` 与分片几何信息。
   - 文件名、MIME、业务场景和临时标记暂不在此阶段写入，会延后到 `merge` 补齐。
   - 同步一份空快照到 Redis。
7. 最终统一返回服务端真实进度快照。

## `upload`：上传单个分片

1. Controller 通过 `FileInterceptor` 接收 multipart 分片文件，并校验 `file` 不为空。
2. `FileUploadSessionService.uploadChunk()` 用 `fileId` 找回当前上传会话；Redis 丢失时会回退到数据库，再结合磁盘分片目录恢复状态。
3. 根据会话记录校验：
   - `chunkIndex` 必须落在 `[0, chunkCount)`。
   - 当前分片大小必须与会话约定的预期大小一致。
4. `FileStorageService.saveChunkBuffer()` 将分片写入非公开临时目录；若同序号分片已存在且大小一致，则视为重复上传，不重复累计。
5. 每次分片上传后，服务端都会重新扫描临时目录，按真实分片快照修正：
   - `uploadedChunkIndexes`
   - `uploadedBytes`
   - `uploadedChunkCount`
   - `status`
6. 更新后的快照同步回 Redis，并返回给前端。

## `merge`：合并分片并校验整文件哈希

1. 客户端提交 `fileId`、整文件 `fileHash`，以及最终保存元数据：`originalName / mimeType / scene / businessType / isTemporary`。
2. 服务端先恢复最新会话，再按磁盘分片目录对账，确认所有分片都已存在。
3. 通过 `FileUploadRedisService.acquireMergeLock()` 获取 Redis merge 锁，防止同一文件并发合并。
4. `FileStorageService.mergeChunks()` 按 `chunkIndex` 顺序把分片流式写入正式文件路径，目标文件名使用 merge 请求体中的 `originalName`。
5. 合并完成后，服务端对正式文件重新流式计算 `SHA-256`，并与前端传入的 `fileHash` 比较。
6. 只有哈希一致时才会：
   - 使用 merge 请求体中的文件名、类型与业务语义创建 `middleware_file_item` 正式文件记录。
   - 把这些最终元数据回写到上传会话，并把会话标记为 `completed`。
   - 删除临时分片目录。
   - 删除 Redis 中的会话快照和 merge 锁。
7. 如果哈希不一致或合并异常：
   - 删除半成品正式文件。
   - 把上传会话标记为 `failed`，记录 `errorMessage`。
   - 保留分片目录，便于后续重试或排查。

## 文件查询与删除

- `FileService.list()` 负责按 `scene / businessType / status / isTemporary` 过滤正式文件列表。
- `FileService.getDetail()` 负责按 `id` 获取单文件详情。
- `FileService.remove()` 负责删除正式文件元数据并尝试删除物理文件。
- 正式文件的 `url / previewUrl` 始终由 `FileStorageService.buildAccessUrls()` 统一组装。

## 描述回写

带键请求使用文件 ID 与描述计算请求指纹。公共数据库幂等服务在同一事务中调用 `FileService.update()` 并记录成功响应。第一次更新提交但响应丢失时，接收重试的实例可以直接返回 `data: true`，文件的审计字段只更新一次。

## 过期清理

- `FileService.cleanupExpiredTemporaryFiles()` 负责清理超过 `UploadTempTtlMs` 的正式临时文件。
- `FileUploadSessionService.cleanupExpiredUploadSessions()` 负责清理超过有效期的未完成上传会话。
- 清理上传会话时会同步删除：
  - 磁盘分片目录。
  - Redis 中的 `meta / chunks / lock` key。
  - 数据库中的过期上传会话记录。
- 上述清理由任务模块统一调度执行，避免临时文件和分片长期残留。
