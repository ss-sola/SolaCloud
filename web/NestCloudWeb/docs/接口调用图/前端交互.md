# 接口调用图

从“运行与审计 → 接口调用图”打开 `/system/api-call-graph`。输入部署了调用图服务的机器上的项目目录，点击“扫描接口”。按方法或路径筛选接口后，页面会先绘制静态调用图。

接口列表的计数旁显示识别出的框架。NestJS 项目使用构建后的 JavaScript 入口启动探针，缺少入口时页面会提示先构建；识别出的路由仍可查看。运行中若缺少有效的源码映射，可在“探针提示”查看相应文件和原因。

选中接口后，项目路径和接口列表收进“切换接口”，画布铺满管理台内容区。点击“全屏”可进一步展开，按 Esc 或点击“退出全屏”返回。方法详情、方法过滤都在画布上按需打开。手机上的管理导航收进顶栏“菜单”。

简单调用图沿调用方向阅读，手机上按可用宽度换行。分支较多时，同一个调用方的下游方法沿扇形展开。主要分支和较大的方法组标出调用方全名与组内方法数，组与组之间留出空白。共享方法只显示一次，各调用方均有连线指向它；递归调用保留回连。初次打开大型图会定位到入口，可拖动画布、滚轮缩放，或点击“适应窗口”查看全貌。

图从一个 HTTP 入口开始，显示当前接口的方法和路径。请求进入后，入口显示整次请求的执行状态和总耗时。方法节点的折叠按钮只收起这条分支的下游，其他展开分支仍可到达的共享方法会继续显示。收起 HTTP 入口可仅看整次请求，再次展开或点击“展开全部”可恢复分支。点击节点主体可查看详情，折叠期间的请求记录仍会继续采集。

点击 HTTP 入口可在画布内查看所选请求的请求头、路径参数、查询参数和请求体。路由匹配或请求体解析完成后，入口会补上已采集的参数。请求结束后还会显示响应头和返回值，保留 HTTP 状态码和总耗时。切换请求记录时，打开的入口详情也随之切换。

采集中尚未到达的响应显示“等待响应…”。响应为空、正文过大或探针省略流式内容时，面板显示对应原因。已遮蔽的敏感字段保留遮蔽标记。旧版探针产生的记录仍可查看其状态和耗时。

扫描完成后，可在接口列表或调用图上点击“启动探针”。等待目标端口监听后，用原客户端向该端口发送请求。一个项目共用一个探针，采集期间可用“切换接口”查看同一项目的其他接口，无需重启。更换项目目录前先停止探针。

请求记录按所选接口显示，可跟随该接口最新请求，也可固定一条记录。返回之前的接口可继续查看已保留的请求。旧探针事件缺少接口标识时，页面只展示能通过 HTTP 方法和路径唯一匹配的请求。每个接口最多保留 24 条请求，整个页面最多保留 96 条，达到上限时优先淘汰已完成的请求。断开事件流后可按序号重新连接。停止探针后，当前页面可继续查看已收到的记录。服务配置、权限补丁和启动步骤见[部署与使用](../../../../apps/call-graph-service/docs/接口调用图/部署与使用.md)。

点击方法可查看每次调用的入参、出参、耗时和异常，探针补充的方法也可以展开。单次请求内同一方法超过 100 次调用时，详情按每页 100 条显示。可前后翻页或输入调用序号跳转。选择“跟随最近一次”回到该方法最新记录。

在“字典管理”选择“系统字典”的 `api_call_graph_probe` 分组，可设置单请求的方法调用次数（默认 0）和每次方法调用的快照值数（默认 1,000）。两项独立，填写 0 代表该项不限制。保存后，下次启动探针生效。调用次数达到设置值时，请求显示省略的次数。快照值数达到设置值时，详情显示截断标记，该次调用仍有执行状态和耗时。

选中一次请求后，标为“未执行”的节点表示这次记录没有该方法的进入事件。静态图包含条件分支。若请求摘要显示“已省略 N 次调用”，也可能有实际发生的调用未被记录。

匿名路由处理器、内联回调和数组映射的匿名函数会自动折叠。用变量或属性命名的箭头函数可以正常显示。打开图上方的“过滤方法”，可按方法名或源码位置搜索，点击“定位”移到该节点，勾选一个或多个方法将其隐藏。

每次打开接口图时，“过滤静态方法”默认开启。仅做本地同步计算的 JS/TS 方法（如对比版本号）会自动隐藏，并在过滤列表中勾选。关闭开关可以显示这些方法，手动隐藏的方法仍保持勾选。查库、接口请求、等待或无法判断的方法会保留。探针补充的方法使用相同规则。工具栏括号内是当前过滤的方法数，同一方法仅计一次。点击“清除过滤”会关闭开关、清空逐项勾选并恢复所有具名方法。过滤可在探针运行期间调整，恢复显示后仍能查看调用记录。

执行中节点显示金色流光边框，连线上的光点沿调用方向移动。正常返回后路径变为绿色，异常为红色，缺少返回记录的调用以虚线标记。系统启用减少动态效果时保留状态文字、颜色和箭头。匿名节点或被过滤的中间方法会被跨过，运行态连线依据该次请求实际经过的调用实例连接两端，未走过的分支保持灰色。

实时收到方法成功返回时，对应连线还会闪过一次绿色流光。即使方法在同一批界面刷新内开始并结束，也能看到经过的路径。查看历史请求或断线续读已有记录时，页面直接显示已记录的状态和耗时。
