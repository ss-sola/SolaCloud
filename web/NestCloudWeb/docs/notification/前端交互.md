# notification 前端交互

## 页面入口

- 运行时菜单组件标识为 `notification`。
- 页面进入后会并行请求通知总览、公告列表、站内信列表、运行态公告、当前登录账号运行态站内信、未读数、字典和 `/api/system/accounts/options` 账号选项列表。

## 顶部动作

- `刷新数据`：重新拉取公告、站内信、运行态、未读数和相关字典/账号数据。
- `新增公告`：打开公告弹窗。
- `发送站内信`：打开站内信发送弹窗。
- 顶部信息条展示服务名、能力数和当前页说明。

## 公告列表交互

- 支持按关键词和发布状态筛选；发布状态来自 `notification.publish-state` 字典。
- 支持对 `ID`、`生效时间`、`发布时间` 进行排序。
- `新增公告` / `编辑` 使用同一弹窗，表单包含标题、内容、发布状态、生效开始和生效结束。
- `删除` 需要确认后才执行。

## 站内信列表交互

- 支持按接收账号 ID 和已读状态筛选；已读状态来自 `notification.read-state` 字典。
- 支持对 `ID`、`发送时间` 排序。
- 只有当前登录账号作为接收人且消息未读时，才显示 `标记已读` 按钮；其他情况显示“仅接收人可标记”。

## 发送站内信弹窗

- 表单包含标题、发送模式、内容、接收账号筛选和接收账号多选框。
- 接收账号数据来自 `GET /api/system/accounts/options`，只消费账号 ID、账号名和显示名三项轻量字段。
- 发送模式来自 `notification.send-mode` 字典，支持“指定账号”和“广播”。
- 指定账号模式下必须至少选择一个接收账号；广播模式下会向当前全部启用账号发送。

## 运行态预览交互

- `刷新运行态`：重新拉取运行态公告、当前登录账号运行态站内信和未读数。
- `刷新未读数`：单独更新当前登录账号未读数。
- `全部已读`：需要确认后，将当前登录账号全部未读站内信标记为已读。
- 运行态公告只展示已发布且仍在生效期内的公告。
- 运行态站内信和未读数只针对当前登录账号，不支持按任意接收账号切换。

## 交互反馈

- 页面顶部统一显示成功/失败提示，如“公告保存成功”“站内信发送成功”“已处理 2 条站内信”。
- 公告列表或站内信列表为空时分别显示“暂无公告数据”“暂无站内信数据”。
- 两个分页区分别支持切页和修改每页条数。
