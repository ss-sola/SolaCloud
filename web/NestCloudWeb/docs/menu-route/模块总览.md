# menu-route 模块总览

## 模块职责

`NestCloudWeb` 中的系统管理菜单与页面绑定，当前统一由运行时菜单里的 `path / component / icon` 驱动。前端不再通过 `routeName` 或 `code` 维护额外页面映射。

## 当前定位

- `src/app/App.tsx` 统一把受保护入口收敛到 `/system`，根路径和兜底路径都会回落到该入口。
- `src/shared/layouts/SystemLayout.tsx` 负责按当前地址匹配运行时菜单，并把 `component` 交给系统页宿主；当地址是 `/system` 或未命中系统菜单时，会先跳到首个可访问系统页。
- `src/app/routes/routeRegistry.ts` 负责路径规范化、首个可访问系统页解析、分组判断和 `component` 元信息读取。
- `src/modules/system/pages/pageRegistry.tsx` 维护 `component -> React/legacy` 页面定义，`menu-route` 已切到 React。
- `src/modules/system/pages/MenuRoutePage.tsx` 负责菜单管理页本身的列表、弹窗、树形父级选择、权限码勾选、批量状态更新和排序提交。
- `src/modules/system/api/menuRouteApi.ts` / `src/modules/system/api/permissionApi.ts` 负责菜单和权限的 typed API 调用。
- `src/modules/system/utils/MenuRouteTreeUtil.ts` 负责树表格排序、树行展开和父级下拉选项构建。
- `src/shared/menuIconResolver.ts` 负责把数据库中的 `icon` 名称解析到 `public/assert/svg/**` 下的 SVG 资源。

## 关键规则

- `path` 决定浏览器地址：`/system/<normalized path>`。
- `component` 决定实际页面绑定键，例如 `dictionary`、`menu-route`、`service-monitor`。
- `/system` 根路径和无效系统路径会回落到运行时菜单树中的首个可访问页面。
- `code` 只作为后端稳定标识，不再参与前端页面映射。
- `icon` 只保存 SVG 名称，不保存完整路径。
- 菜单管理页列表中的 `Icon` 列只展示解析成功的 SVG 预览，不再直接显示 icon 名称文本；icon 名称仍在编辑弹窗中维护。
- `meta.group = true` 的菜单节点在侧边栏中按可折叠分组按钮渲染，当前激活页所在分支会自动展开。
