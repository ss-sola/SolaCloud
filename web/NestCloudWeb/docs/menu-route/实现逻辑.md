# 实现逻辑

## 运行时菜单驱动链路

1. `AuthBootstrap` 在应用启动时调用 `loadCurrentAccount()`。
2. 认证状态层读取 `/api/system/runtime-permissions/current`，拿到运行时菜单树。
3. `SystemLayout` 先通过 `RouteRegistry.findMenuByPath(...)` 用当前地址匹配菜单节点；若当前地址是 `/system` 或未命中系统菜单，再通过 `RouteRegistry.findFirstPagePath(...)` 找到首个可访问系统页并执行回跳。
4. 匹配成功后，布局层把 `currentMenu.component` 交给 `SystemPageHost`。
5. `SystemPageHost` 通过 `pageRegistry` 命中 `menu-route` 对应的 `MenuRoutePage`，并由 `SystemPageFrame` 承载标题、描述、顶部动作与信息条。

## 路由与绑定规则

- `RouteRegistry.resolvePath(...)` 统一把菜单 `path` 规范化为 `/system/<path>`。
- `RouteRegistry.findFirstPagePath(...)` 按运行时菜单树的顺序深度优先扫描，返回首个启用、可见且已接入前端页面配置的系统路径。
- `RouteRegistry.getPageConfig(...)` 只接受 `component`，不再接受 `routeName` 或 `code` fallback。
- `RouteRegistry.isGroup(...)` 用 `meta.group = true` 或“有子节点且无 component”识别分组菜单。
- `SystemLayout` 只在当前菜单存在 `component` 时渲染系统页；对于 `/system` 根路径和未命中系统菜单的路径，会优先回落到首个可访问页面，仅在没有任何可用系统页时才展示“页面不存在”。
- `meta.group = true` 的菜单节点在侧边栏中渲染为可折叠按钮，当前激活菜单所在的父级分组会自动展开。

## 菜单图标解析

- 图标资源统一放在 `web/NestCloudWeb/public/assert/svg/**`，按 `system / resource / access / observe / monitor` 分目录存放。
- `menuIconResolver.ts` 维护显式 manifest，把数据库中的 `icon` 名称映射为 public URL。
- 侧边栏渲染菜单时通过 `resolveMenuIconUrl(...)` 输出 `<img>`，因此业务数据里只需要保存名称，例如 `dictionary`、`system-access-group`。

## 菜单管理页交互

- 菜单管理页已迁移到 `src/modules/system/pages/MenuRoutePage.tsx`，页面查询、树表格、弹窗和反馈全部由 React 状态驱动，不再依赖 `document.getElementById`、`innerHTML` 或 `window.bootstrap.Modal`。
- 列表数据通过 `menuRouteApi.ts` 获取，树形展示和父级下拉都由 `MenuRouteTreeUtil` 基于 `parentId` 关系构建。
- 页面保留现有行为：本地树排序、展开/折叠、批量启停、可见节点排序提交、图标名称预览和权限筛选多选。
- 列表中的 `Icon` 列只显示解析后的 SVG 预览，不再把 icon 名称文本直接渲染到表格里。
- 编辑已有菜单时，`code` 输入框只读；保存时更新接口也不会再提交 `code`。
- 菜单编辑弹窗使用加宽弹窗，保证路由表单与权限绑定区域有足够横向空间。
- 当表单或权限绑定区域内容较长时，滚动条保持在弹窗内部，不再落到页面外层。
- 表单保存的数据模型已收口为 `name / path / parentId / component / redirect / icon / sort / isEnabled / isHidden / permissionCodes / meta`。
- 菜单变更成功后会调用认证状态层重新加载运行时菜单，确保侧边栏与当前权限菜单同步更新。
