# system-page-frame 实现逻辑

## 系统入口与登录壳层对齐

- `App.tsx` 已把受保护入口统一挂到 `AppShellLayout` 下，`/` 不再固定回落到 `/system`。
- `LoginPage.tsx` 继续复用 `legacy-style.css` 中的 `login-gate / login-panel` 样式承接登录门禁。
- 登录成功后，若守卫传入的 `state.from` 仍是受保护路径，则优先跳回原目标页；否则统一回到 `/`，再由共享壳层根据运行时菜单分发到首个可访问叶子页面。
- `AppShellLayout.tsx` 会先通过 `RouteRegistry.findFirstPagePath(...)` 解析全局默认页和当前一级域默认页，因此 `/system` 及未命中真实页面组件的一级域路径都会先回落到真实页面，而不是直接展示“页面不存在”。

## 侧边栏分组交互

- `meta.group = true` 的菜单节点在 React 壳层中渲染为可折叠按钮，沿用旧版侧边栏的层级结构。
- 当前激活菜单所在的分组链路会自动展开，避免刷新或直接访问深层系统路径后出现“当前页已打开但侧边栏父分组被折叠”的割裂状态。
- 旧版独立 `控制台` 入口已从系统侧边栏移除，系统入口直接由运行时菜单驱动。

## Frame 状态写回约束

- 页面顶部动作区通过 `SystemPageFrameContext` 的 `actions` 字段回写到统一 frame。
- `actions` 一旦依赖每次 render 都变化的回调或 JSX 节点，`setFrameState` 就会持续触发，最终出现 `Maximum update depth exceeded`。
- 因此，所有会被 `topbarActions` 引用的刷新回调，都必须只依赖稳定对象，优先使用 `queryClient.refetchQueries({ queryKey })`，并将 `useCallback` 依赖收敛到 `[queryClient]`。

## 账号头像上传交互

- `AccountPage.tsx` 的头像上传不再直接 `fetch + FormData` 一次性直传，而是统一通过 `AccountApi.uploadFile()` 接到共享上传器。
- 共享上传器会先基于文件源信息计算 `sourceHash`，再结合前端会话 id 生成稳定 `fileId`，调用 `${uploadUrl}/check` 仅提交 `fileId + sourceHash + totalSize + chunkSize + chunkCount` 做校验或复用上传会话；服务端确认 `fileId` 与 `sourceHash` 匹配后返回已落盘分片索引，再按固定分片大小切片，通过 `XMLHttpRequest` 向 `POST ${uploadUrl}` 逐片上传，并在全部完成后调用 `${uploadUrl}/merge`。
- 页面在上传中显示总进度条和实时网速；如果上传中断，重新选择同一文件时，服务端会基于同一个“前端会话 id + sourceHash”对应的 `fileId` 返回已落盘分片索引，页面只补传缺失分片。merge 阶段则提交前端按分片增量计算出的整文件 `fileHash`，并同时提交 `originalName / mimeType / scene / businessType / isTemporary` 作为最终保存元数据。

## 本次修复范围

### 刷新回调稳定化

以下页面已统一改为基于 query key 的刷新方式：

- `DictionaryNamespacePage.tsx`
- `DictionaryPage.tsx`
- `LoginLogPage.tsx`
- `OperationLogPage.tsx`

这些页面都会把 `topbarActions` 写回 frame context，刷新回调不再直接依赖 `overviewQuery`、`itemsQuery` 这类 query 结果对象。

### 选择态数组稳定化

以下页面把 `query.data ?? []` 改为 `useMemo` 生成的稳定数组引用，避免加载态 effect 反复写回相同语义的新数组：

- `AccountPage.tsx`
- `RolePage.tsx`
- `MenuRoutePage.tsx`
