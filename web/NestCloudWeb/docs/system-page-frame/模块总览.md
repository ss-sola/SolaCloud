# system-page-frame 模块总览

## 模块职责

共享页面框架在内容区上沿放置单行顶栏。左侧显示当前页面标题，右侧提供主题开关和账号菜单。点击头像后可登出。桌面端的侧栏与正文分别滚动；窄屏上的导航与正文在顶栏下方一起滚动。配置了 `hideHeader` 的页面使用全部内容高度。

## 当前实现

- `src/app/App.tsx` 已把受保护入口统一收敛到 `AppShellLayout`，根路径会回落到当前账号可访问的首个叶子页面。
- `src/modules/system/pages/LoginPage.tsx` 继续负责登录门禁；登录成功后仍优先回到守卫透传的原目标路径，否则回到 `/` 交由共享壳层继续分发。
- `src/shared/layouts/AppShellLayout.tsx` 负责根据运行时菜单解析当前页面、处理一级域默认页回落，并在命中真实页面组件后挂载 `SystemPageFrameProvider`。
- 共享壳层的侧边栏分组使用按钮折叠 / 展开，当前激活菜单所在分支会自动保持展开状态；隐藏流程页不会显示在菜单中，但仍可通过路由进入页面 frame。
- `src/modules/system/pages/SystemPageFrameContext.tsx` 负责维护页面 frame state，并向子页面暴露 `setFrameState`。
- 具体系统页在自己的 `useEffect` 中回写 `actions`、`serviceLabel` 与 `capabilityLabel`。
- `src/modules/system/pages/AccountPage.tsx` 的头像上传现在通过共享 `ResumableUploader` 接入统一分片协议：页面展示总上传进度与实时网速，中断后重新选择同一文件会继续上传缺失分片。
- `src/shared/api/resumableUploadApi.ts` 负责统一封装唯一上传链路 `check / upload / merge`：`check` 会先基于文件源信息 `sourceHash` 和前端会话 id 生成稳定 `fileId`，再仅提交 `fileId + sourceHash + 分片几何信息` 做校验与续传恢复；`upload` 逐片上传；`merge` 再提交前端 Worker 按分片增量计算出的整文件 `fileHash` 与最终保存元数据，页面只消费上传结果和进度快照。
- 刷新类动作统一通过 `queryClient.refetchQueries` 按 query key 触发，避免把不稳定 query 实例作为回调依赖继续传回 frame context。
- 依赖远端数据清理选择态时，数组回退值需要保持稳定引用，避免 `query.data ?? []` 直接参与 `useEffect` 依赖后形成自激更新。
