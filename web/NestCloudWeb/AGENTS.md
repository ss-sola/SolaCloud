## 前端基座定位约束

- `NestCloudWeb` 是统一前端基座。第一阶段同时承载后台管理和未来前台 / 移动端能力入口；新增能力优先在单项目内按模块演进，不急于拆成多个前端工程。
- 不默认引入 Element / Element Plus，也不要把页面风格固化为传统后台模板；优先复用现有布局、设计变量、Bootstrap 基础能力和项目内组件。
- PC 与移动端优先通过布局分层、响应式适配和局部页面承载实现；未落地的端能力不要提前绘制无效入口、占位按钮或假页面。
- 直播、工作流、编辑器等重依赖必须按模块或路由懒加载，避免影响系统管理基础页面的首屏和基础包体。

## 目录与模块边界约束

- `src` 根目录仅保留 `main.tsx`、类型声明和少量应用级入口；业务实现按 `app`、`modules`、`shared` 分目录落位。
- `app` 只放应用启动、路由注册、全局状态、运行时权限路由映射等应用级能力。
- `modules` 按业务域拆分页面、模块内组件、模块内 API 和适配逻辑；模块私有逻辑不要堆到 `shared`。
- `shared` 只放跨模块复用的 API client、通用组件、布局、样式、无副作用工具和公共类型；不要把某个业务模块的专属判断塞进 `shared`。
- `modules/system/legacy` 是旧管理台迁移阶段的兼容层。迁移旧页面时，DOM 挂载、`window.bootstrap`、`innerHTML`、`document.getElementById` 这类命令式桥接逻辑只允许继续收敛在 legacy 目录或专门的适配组件中；新的 React 页面和新组件不要新增这类实现。
- 系统管理页的路由、标题、描述和运行时菜单映射统一收敛到路由注册层处理；新增菜单驱动页面时，优先补齐统一注册，不要在布局、页面和按钮里重复硬编码路径或菜单码。

## 前端实现约束

- React 组件、路由组件、store、hook 可按前端惯例使用函数式写法；不要为了套用后端约束而把 React 组件改成类组件。
- 无状态格式化、解析、类型转换、请求参数组装、响应结果归一化等通用逻辑，不要散落在页面 JSX 中；统一收敛到 `shared/utils` 或模块自己的 `utils` / `adapter` 中。
- 所有 HTTP 请求统一通过 `src/shared/api` 或模块内封装的 API 层发起；页面组件、布局组件、通用 `utils` 中禁止直接散落 `fetch` 调用。
- 服务端数据优先通过 `ApiClient` + TanStack Query 组织；Zustand 只承载登录态、运行时菜单、跨页面共享 UI 状态等真正需要全局共享的客户端状态，不要用全局 store 代替所有请求缓存。
- 登录态、当前账号、角色码、运行时菜单统一通过认证状态层维护，不要在页面里各自读 cookie、重复请求当前账号，或绕过统一状态直接拼权限逻辑。
- 前端权限控制只负责可见性、导航和交互收敛；后端接口权限校验仍是唯一可信边界，不能因为前端隐藏了按钮或菜单就默认安全。
- 前端改造优先做局部刷新和状态保留，不用整页重载解决普通交互；高频轮询场景不要引入全量重绘。
- 接口字段命名、分页字段和返回结构优先保持与后端协议一致，继续使用 `pageNum`、`pageSize`、`list` 等现有约定；不要在前端额外发明一套不兼容命名。
- 前端配置统一通过集中配置模块、常量或 Vite 运行时能力处理；禁止在业务组件中散落直接读取 `process.env`。如需新增前端环境变量或代理目标，必须同步更新对应配置入口和文档。
- 业务代码中不要长期保留 `console` 调试输出；需要保留的用户提示、错误提示和加载反馈应使用页面内可见的交互反馈方式。

## 文档与验证约束

- `web/NestCloudWeb` 视为仓库内独立前端项目。涉及跨模块改动、新增接口、新增配置项、新增缓存、权限菜单模型调整、布局体系调整、超过 3 个文件的业务改动时，需在本项目的 `docs/plan` 目录下建立计划；任务完成后，再把正式说明同步写入本项目的 `docs/<模块>/` 目录。
- 新增或修改接口、登录态流程、权限菜单、布局结构、代理配置时，必须同步更新对应模块文档或项目级文档，`docs/plan` 不能代替正式文档。
- 自动化验证优先使用本项目命令：`pnpm --dir web/NestCloudWeb typecheck`、`pnpm --dir web/NestCloudWeb test:unit`、`pnpm --dir web/NestCloudWeb build`。
- 测试文件继续放在与 `src` 同级的 `src/__tests__/` 目录；新增测试优先覆盖登录态、路由守卫、API 适配、权限菜单映射和 legacy 页面桥接等高价值规则。
- 前端自动化测试默认使用可控 mock 输入，不直接依赖真实后端网络；真实联调放在手工验证或专项验证中执行。
