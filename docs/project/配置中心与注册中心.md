# 配置中心与注册中心

## 1. 配置中心接入流程

公共配置接入位于 `../NestCloud-Sdk/src/config-center/index.ts`。

当前项目采用的是 Nacos-like 简化控制面模型：`NestCloud` 同时承担配置中心与注册中心职责，业务服务统一通过这一控制面完成配置拉取、服务注册与服务发现。

### 本地加载

`initConfigCenter()` 启动时会先调用 `loadConfig()` 读取本地配置文件，并写入内存态配置。

默认行为：

- 未显式指定文件时，读取当前工作目录下的 `.env`
- 支持 `json`、`yaml/yml`、`env` 三类格式

### 远程同步

当应用启用配置中心能力后，客户端会调用：

- `GET {registryUrl}/api/config-files/client/pull`

这里复用了 `RegistryUrl` 作为控制面入口地址。当前语义不是“误命名”，而是简化控制面实现的一部分：同一个入口同时承载配置拉取与注册中心访问。

请求参数：

- `serviceName`
- `names`

### 合并规则

客户端以远程 `mergedConfig` 为基础，再覆盖本地同名项。启动和热刷新共用本服务的配置 DTO，将 `false`、`0` 等文本按布尔语义转换。完整候选配置通过校验后才替换当前快照。启动拉取失败会校验并使用本地配置，后续刷新失败保留上一份有效配置。

### 统一读取方式

业务代码必须通过 `getConfig` 与 `ConfigKey` 读取配置，禁止绕过为 `process.env`。

## 2. 配置中心服务端职责

`../NestCloud/src/config-center/service/config-file.service.ts` 负责：

- 配置草稿创建与更新
- 配置发布与版本递增
- 按名称聚合配置版本
- 按服务名与配置名拉取已发布配置
- 多份配置内容解析并深度合并

管理页通过 `POST /api/config-files` 保存草稿。编辑已发布版本会得到草稿，原版本内容和摘要保留。发布前验证配置格式和根节点；失败时草稿可继续编辑，上次成功发布的版本仍可拉取。

当前支持的配置格式：

- `json`
- `yaml`
- `yml`
- `env`
- `properties`

## 3. 注册中心客户端流程

注册中心客户端位于 `../NestCloud-Sdk/src/client/registry-client.service.ts`。

### 注册

三个业务服务在 `NodeEnv=production` 时启用注册和发现，监听成功后向以下接口注册：

- `POST {registryUrl}/api/registry/register`

上报内容包含：

- `id`
- `name`
- `host`
- `port`
- `baseUrl`（可选，例如 `https://middleware.example.com/api`）
- `metadata`

业务服务通过 `ServiceBaseUrl` 指定完整对外地址。省略时，新客户端根据 `ServiceHost`、`Port` 和 `GlobalPrefix` 广播自己的地址。消费端在选出实例后优先使用其 `baseUrl`，再拼接业务路由，保留协议、端口和路径前缀。旧记录继续使用 `http://host:port`。完整地址与实例 ID 独立，多个实例共用网关域名时仍可按各自的主机与监听端口续约。

### 心跳

客户端定时调用：

- `POST {registryUrl}/api/registry/heartbeat/{instanceId}`

若中心返回实例不存在，客户端停止当前心跳并重新注册。首次注册和重新注册采用同一流程。请求失败后等待 3 秒继续重试，直到成功或服务关闭。心跳传输失败会记录日志并等待下一次心跳。

业务实例默认每 30 秒发送心跳，注册中心和网关默认使用 180 秒的实例租约。

### 服务同步

客户端定时调用：

- `GET {registryUrl}/api/registry/all`

同步结果会落到本地缓存，供服务发现逻辑使用。

批量文件详情查询和文件描述更新通过该缓存选址并直连 middleware-service。有可替换地址时，符合重试条件的请求优先选择未尝试的地址。多个实例共用网关地址时由网关选择实际后端。[调用策略与配置](../../../NestCloud-Sdk/docs/http/链路传递与重试.md)

### 网关只发现模式

gateway-service 在注册模式下复用 SDK 的只发现选项，通过相同的 `GET /api/registry/all` 更新内存快照。网关使用业务实例的 `host` 和 `port` 作为 HTTP 上游，避免使用可能指向统一入口的 `baseUrl`。摘除及空快照在下一次成功同步生效，快照和实例租约过期后返回 503。

## 4. 注册中心服务端职责

`../NestCloud/src/registry-center/registry.service.ts` 负责：

- 注册实例
- 注销实例
- 处理心跳续约
- 服务发现
- 获取服务总览与审计日志
- 清理超时实例

存储策略：

- 配置了 Redis 时使用 `RedisRegistryStore`
- 未配置 Redis 时使用 `MemoryRegistryStore`

Redis 清理以扫描时的实例记录为条件，在实例哈希内原子删除过期租约，再同步服务索引、计数和审计。服务发现读取实例哈希，已续约的实例继续参与路由。租约脚本只操作一个键，可沿用原有 Redis 键前缀。
